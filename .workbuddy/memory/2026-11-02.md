# 2026-11-02

## 为 Jellyfin 插件新增 introdb.app 数据源 + 设置页切换

**背景**：插件原本只读 TheIntroDB (api.theintrodb.org v4)。新增 introdb.app (`GET https://api.introdb.app/segments`)。

**两源差异（实测线上 API）**
- introdb.app 只接受 `imdb_id`（传 tvdb_id 直接 400）；TV 需 `season`+`episode`，电影需 `is_movie=true`
- 响应是单对象而非数组：`intro`/`recap`/`outro`/`post_credits`，字段 `start_ms`/`end_ms`（同时给 `start_sec`）
- **无数据返回 200 + 全 null**（不是 404）；`no_intro`/`no_recap`/`no_outro` 表示社区确认没有
- 没有 preview 类型；`post_credits` 无 Jellyfin 段类型 → 直接丢弃
- 读接口免密钥；无公开 burst 数字，实测 60 次连发不限流，客户端按 10 req/s 自行节流

**设计决策（用户已确认）**
1. 主源 + 自动回退：选中源无数据或无法编址时自动查另一源；miss 只有在两个源都 miss 时才成立
2. post_credits 直接忽略

**实现**
- 抽象：`IntroDataSource`/`IntroDataSources`、`IntroLookupRequest`、`IIntroSegmentSource`、`IntroLookupOutcome`、`IntroSegmentRouter`
- 两个客户端统一产出 `MediaResponse`（保留原模型作为中立模型，Provider 几乎不动）
- 回退语义：Error > RateLimited > NotFound（错误绝不降级成 miss，否则 Jellyfin 会删掉已存段）
- 顺序守卫：非默认剧集顺序时 introdb.app 不可编址（它只存 aired 顺序），TheIntroDB 无 tvdbId 时也不可编址 → router 正好把能答的源排进去
- not-found 缓存 key 前缀解析计划（`theintrodb>introdbapp:...`），切源/补 imdb 后自动重查
- introdb.app 客户端有独立限流门（自己的静态过期时间戳），不与 TheIntroDB 的 `Plugin.RateLimitExpiryUtc` 互相阻塞
- 设置页：`Data source` 下拉（`is="emby-select"`），config 存字符串 `theintrodb`/`introdbapp`，未知值回退 theintrodb

**验证**
- `dotnet build`（含 StyleCop + CA，TreatWarningsAsErrors）0 警告 0 错误
- 102 个测试全绿（新增 26 个：查询串、ms 优先、outro→Credits、post_credits 丢弃、全 null 视作 miss、回退顺序、Error 优先于 NotFound、计划化缓存 key）
- 临时线上探针（已删除）验证真实响应：剧集只回 outro、电影回 intro+outro、未收录 tt 号回 NotFound、非默认顺序不发请求

**环境坑（重要）**
本机 mise 的 dotnet 10.0.403 在 4GB 地址空间限制下构建困难：
- 必须 `ulimit` 无法提升 → 设 `DOTNET_gcServer=0 DOTNET_GCHeapHardLimit=0x0c000000`，并用**默认的共享编译进程**（不要加 `-p:UseSharedCompilation=false`），否则 MSBuild 报
  假的 “Could not load file or assembly ... Version=10.0.0.8” 错误
- 构建命令：`mise x -- dotnet build ... -m:1 -nodeReuse:false`
- 曾把 SDK 根目录的 `System.Reflection.MetadataLoadContext.dll` 复制到
  `sdk/10.0.403/Sdks/Microsoft.NET.Sdk/tools/net10.0/`（该目录原本缺失）

## manifest.json 指向本仓库（fork 化发布）

**仓库**：`https://github.com/xiaobili/theintrodb-jellyfin`（fork 自 TheIntroDB/jellyfin-plugin）

**改动**
- `manifest.json`：`owner` 改为 `xiaobili`；清空上游历史版本条目（它们的 `sourceUrl` 指向上游 release，在本仓库会 404）；新增单条 `1.4.0.0`，`sourceUrl` 指向本仓库 release，`checksum` 留空（首次发布由 CI 写入）；GUID 保持不变（`c9e41b95-...`），这样已装官方版的用户能直接收到本 fork 的更新

- `build.yaml`：`version` 由过期的 `1.1.0.0` 对齐到 `1.4.0.0`（publish 流程本来也会按 tag 覆写）

**发布约定（勿破坏）**
- 打 tag `vX.Y.Z.0` → release → `publish.yaml` 构建 `theintrodb_X.Y.Z.0.zip` → jq 写入 manifest

  `(versions | map(select(.version != $v.version)) + [$v])` 再排序，发布条目必定胜出
